# JeshApps Design System

Shared design tokens for the projects in `~/JeshApps`.

Figma is where the design gets authored. This repository is the engineering source of truth: it holds normalised tokens imported from Figma and builds them into CSS and JSON that the other projects consume.

## Figma collections

The tokens come from the Figma NDS variable collections. Each one has its own export and its own token file:

| Figma collection | Modes | Token file |
| --- | --- | --- |
| NDS / Primitives / Color | Base | `tokens/primitives/colors.json` |
| NDS / Primitives / Size | Base | `tokens/primitives/size.json` |
| NDS / Primitives / Spacing | Base | `tokens/primitives/spacing.json` |
| NDS / Primitives / Radius | Base | `tokens/primitives/radius.json` |
| NDS / Primitives / Elevation | Mode 1 | `tokens/primitives/elevation.json` |
| NDS / Brand / Color | Base, FortressMinds, Jeshnegi, NegiFlow | `tokens/brands/colors.json` |
| NDS / Typography | Base, FortressMinds, Jeshnegi, NegiFlow | `tokens/typography/typography.json` |
| NDS / Semantic / Color | Light, Dark | `tokens/semantics/colors.json` |
| NDS / Components | Base | `tokens/component/components.json` |

Files for single-mode collections hold the token tree directly. Files for multi-mode collections are keyed by the exact Figma mode name.

### Layers

Primitives hold raw values. Brand tokens reference primitives, and Typography tokens are raw values per brand. Semantic tokens reference primitives, brand tokens or other semantic tokens; `color.border.error`, for example, points at `{color.status.error}`. Component tokens may reference any layer, though right now they only reference size primitives.

Brand and theme are independent. Every brand uses the same two Semantic modes, `Light` and `Dark`, and a semantic reference such as `{brand.color.primary}` resolves against whichever brand is selected. So `color.action.primary` is `sky.500` for NegiFlow and `amber.500` for FortressMinds, in both Light and Dark.

## Pipeline

```text
Figma -> docs/figma-export/ -> tokens/ -> dist/
```

* `docs/figma-export/` is the authoring input. Never edit it by hand.
* `tokens/` is the normalised engineering source, generated by the importer.
* `dist/` is the generated output. It's gitignored.

```bash
for f in docs/figma-export/*.zip; do
  unzip -o "$f" -d docs/figma-export/extracted
done
```

### Import

```bash
npm run tokens:import
```

The importer reads `docs/figma-export/extracted/` and treats that folder as read-only. First it confirms every extracted folder still matches its zip. Then it:

* turns Figma alias metadata into references such as `{blue.600}`, so values aren't flattened
* keeps values that are already references
* strips Figma `$extensions` and keeps `$type`, `$value` and `$description`
* confirms each alias points at a token that exists in the collection Figma names

### Validate

```bash
npm run tokens:validate
```

This checks that:

* every token file exists, parses as JSON and has no `$extensions`
* Brand and Typography have the same modes, and Semantic has exactly two modes, `Light` and `Dark`
* all modes of a collection have the same token paths
* token paths are unique across collections
* references follow the layer rules above, resolve in every brand/theme combination and contain no cycles

It also lists any Figma WEB code-syntax names that differ from the CSS variable names the build emits.

### Build

```bash
npm run tokens:build
```

This validates the sources, builds `dist/`, then validates the output (`npm run tokens:validate -- --distribution`).

## Distribution

```text
dist/css/tokens.css             all primitives
dist/css/components.css         component tokens
dist/css/brands/<brand>.css     brand + typography + semantic theme
dist/css/<brand>.css            bundle: imports the three files above
dist/tokens/tokens.json         primitives + components
dist/tokens/brands.json         { "brands": { <mode>: ... } }
dist/tokens/typography.json     { "typography": { <mode>: ... } }
dist/tokens/semantics.json      { "semantics": { "Light": ..., "Dark": ... } }
```

The `<brand>` slugs are `base`, `jeshnegi`, `negiflow` and `fortressminds`.

In CSS:

* References stay as `var()`, so `--color-action-primary: var(--teal-700)`.
* Variable names come from the token path: `color.background.default` becomes `--color-background-default`.
* Dimensions get `px` (size, spacing, radius, elevation, font sizes, line heights, border widths). Font weights stay unitless.
* Each brand file puts its light theme on `:root`. The dark theme applies under `prefers-color-scheme: dark` unless `data-theme="light"` is set, and always under `:root[data-theme="dark"]`.

To use a brand, import its bundle:

```css
@import "@jeshapps/design-system/css/negiflow";
```

`css/<name>` maps to `dist/css/<name>.css`, so `css/brands/negiflow` and `css/tokens` work too. The older `dist/css/negiflow.css` path still resolves.

The JSON files mirror `tokens/` with references preserved, for platforms other than CSS, such as React Native.

## When Figma changes

1. Export the updated NDS variable collections from Figma.
2. Replace the matching zip and extracted folder under `docs/figma-export/`.
3. Run `npm run tokens:import`.
4. Run `npm run tokens:validate`.
5. Run `npm run tokens:build`.
6. Review the diff under `tokens/`.
7. Commit.


# 1. Extract the newly downloaded Figma ZIPs
for f in docs/figma-export/*.zip; do
  case "$f" in
    *"NDS _ Brand _ Color.zip") dir="NDS / Brand / Color" ;;
    *"NDS _ Components.zip") dir="NDS / Components" ;;
    *"NDS _ Primitives _ Color.zip") dir="NDS / Primitives / Color" ;;
    *"NDS _ Primitives _ Elevation.zip") dir="NDS / Primitives / Elevation" ;;
    *"NDS _ Primitives _ Radius.zip") dir="NDS / Primitives / Radius" ;;
    *"NDS _ Primitives _ Size.zip") dir="NDS / Primitives / Size" ;;
    *"NDS _ Primitives _ Spacing.zip") dir="NDS / Primitives / Spacing" ;;
    *"NDS _ Semantic _ Color.zip") dir="NDS / Semantic / Color" ;;
    *"NDS _ Typography.zip") dir="NDS / Typography" ;;
  esac
  mkdir -p "docs/figma-export/extracted/$dir"
  unzip -o "$f" -d "docs/figma-export/extracted/$dir"
done

# 2. Import
npm run tokens:import

# 3. Build + validate distribution
npm run tokens:build

# 4. Run tests
python3 -m unittest discover tests

Change token values in Figma and re-import. Don't hand-edit `tokens/` or `dist/`.

Don't rename or delete tokens without warning, because consuming projects may depend on them.

## Using tokens

Use semantic tokens in application code where you can:

```text
color.background.default    rather than    #0F172B
```

Save primitive tokens for defining the design system itself, or for cases where no semantic token fits.

Projects that may consume this design system include Stakemate, NegiFlow, NegiFlow Platform, JeshNegi, FortressMinds and Customer Feedback Intelligence.
